## Project Overview

**pyGoogleMoogle** is a serverless Slack bot that responds to @mentions and slash commands with witty Final Fantasy Moogle-style responses. It uses the **Bedrock Converse API** (model-agnostic) and is currently running **Amazon Nova Lite** while Anthropic model access is pending approval. Switching to Claude Haiku 4.5 requires only a Terraform variable change — see **Pending** below. The bot uses tool calling to look up FFXI items on FFXIclopedia directly (saving inference tokens vs. asking the model to recall item data) and AgentCore Memory for multi-turn conversations.

### Key Architecture
- **API Gateway**: `/googlemoogle/events`, `/googlemoogle/slash`, `/googlemoogle/health`
- **API Key**: Auto-generated by AWS (not manual) via usage plan
- **Authorizer**: Lambda authorizer validates `api_key` query parameter (simplified - Slack signatures moved to Initial Lambda)
- **Initial Lambda**: Validates Slack signatures, computes session_id/actor_id, posts immediate "thinking" messages via `chat.postMessage`, sends to SQS. Handles `/moogle reset` synchronously (clears AgentCore Memory, skips SQS)
- **Processing Lambda**: Loads prior turns from AgentCore Memory → calls Bedrock Converse API (currently Nova Lite, swap to Claude via `BEDROCK_MODEL_ID`) with tool use (ffxi_item_lookup) → posts final responses → saves user+assistant turns to AgentCore Memory
- **AgentCore Memory**: Stores per-session conversation turns (7-day expiry, 30-min idle window enforced client-side)
- **SQS Queue**: Async processing (no DLQ configured)
- **Remote State**: Terraform uses S3 + DynamoDB backend

## Environment Variables

| Variable | Default | Purpose |
|----------|---------|---------|
| `LOG_LEVEL` | ERROR | Logging level (DEBUG, INFO, WARNING, ERROR, CRITICAL) |
| `BEDROCK_MODEL_ID` | `amazon.nova-lite-v1:0` | Bedrock model ID — change to Claude once access approved (see Pending) |
| `BEDROCK_REGION` | (Lambda's `AWS_REGION`) | Bedrock region for Converse API calls |
| `AGENTCORE_MEMORY_ID` | (Terraform output) | AgentCore Memory resource ID for conversation state |
| `SESSION_IDLE_MINUTES` | `30` | Minutes of silence that end a conversation (client-side idle boundary) |
| `SLACK_BOT_TOKEN` | (required) | Slack OAuth token used by Initial + Processing Lambdas |
| `SLACK_SIGNING_SECRET` | (required) | Signature verification in Initial Lambda |

Set via Terraform or AWS Console Lambda configuration.

**Notes:**
- Amazon Nova Lite is enabled by default in Bedrock — no manual model access step needed for Nova.
- Claude models require explicit opt-in: AWS Console → Bedrock → Model access.
- AgentCore Memory events have a 7-day hard expiry (Terraform); the 30-min idle window is enforced in code by filtering event timestamps.
- `AGENTCORE_MEMORY_ID` is set on both Initial Lambda (for `/moogle reset`) and Processing Lambda (for load/save).

## Technical Discoveries

- **x-api-key naming conflict**: `x-api-key` appears to be a reserved name in AWS API Gateway. When used as query parameter, it may be filtered/stripped before reaching Lambda authorizer. Using `api_key` works fine. Debug logging added to investigate.
- **Critical idempotency bug fixed**: Original `generate_request_id()` used `time.time()` as fallback. Fixed to use Slack's stable `event_id` and `trigger_id`.
- **API Gateway Authorizer IAM**: API Gateway needs separate IAM role with trust policy allowing `apigateway.amazonaws.com` to assume it.
- **Terraform Deployment Caching**: API Gateway deployments are immutable. Used `create_before_destroy` lifecycle and deployment triggers to force redeployment.

## Key Design Decisions

1. **Idempotency**: Uses Slack's `event_id` (events API) and `trigger_id` (slash commands) - NOT `time.time()`
2. **Authorizer**: Only validates API key. Slack signatures validated in Initial Lambda.
3. **Response Method**: Both @mentions and slash commands use `chat.postMessage` Web API (no `response_url`)
4. **API Key Location**: Query parameter `?api_key=XXX` (header-based `x-api-key` has conflicts with API Gateway)
5. **Logging**: Default ERROR level for minimal CloudWatch costs. Set to DEBUG temporarily for troubleshooting.
6. **Converse API**: LLM client uses `bedrock-runtime.converse()` (not `invoke_model`). This is model-agnostic — switching between Nova and Claude is a `BEDROCK_MODEL_ID` change only, no code edits.
